## ARCHITECTURE
pattern: Modular Monolith, N-Tier (NestJS standard layers)
communication_sync: REST /api/v1/ (NestJS controllers)
communication_async: Transactional Outbox → BullMQ → HTTP POST
multi_tenant_strategy: Row-Level isolation (tenant_id FK in all tables)
auth_strategy: JWT Access (15min, HttpOnly cookie) + Refresh Token Rotation (7d, path-scoped)
rbac_roles: admin, editor
api_public_auth: API Keys (HMAC-SHA256 hashed + pepper, prefix+publicId+secret format)
webhook_security: HMAC-SHA256 signed, timingSafeEqual verified, anti-replay TTL

## BACKEND MODULES (apps/api/src/modules/)
auth/
  endpoints: POST /api/v1/auth/register-admin, POST /api/v1/auth/login
             POST /api/v1/auth/refresh, POST /api/v1/auth/logout, GET /api/v1/auth/me
  guards: JwtAuthGuard, RateLimitGuard
  decorators: @CurrentUser, @RateLimit, @Idempotent
  dtos: LoginDto, RefreshTokenDto, RegisterAdminDto (nestjs-zod)
  strategy: JWT HttpOnly cookie, refresh token rotation

users/
  responsibilities: CRUD users, RBAC assignment
  scoping: always filtered by tenant_id

tenants/
  responsibilities: tenant provisioning, plan management, data isolation
  isolation: tenant_id FK, no cross-tenant queries ever

testimonials/
  lifecycle: draft → pending → approved → published | rejected
  controllers: TestimonialsController, TagsController, CategoriesController, PublicTestimonialsController
  services: TestimonialsService, TagsService, CategoriesService, ScoringService
  imports: AnalyticsModule, FeatureFlagsModule, WebhooksModule, CloudModule, TenantsModule
  dtos: CreateTestimonialDto, UpdateTestimonialDto, ModerateTestimonialDto,
        PublicTestimonialsQueryDto, UploadImageDto, AttachVideoDto, SubmitPublicTestimonialDto
  constraints: content min 10 chars, rating 1-5

webhooks/
  pattern: Transactional Outbox (outbox_events table)
  services: WebhooksService, OutboxService, OutboxProcessor, WebhookOutboxHandler,
            HttpWebhookDispatcher, HttpResilienceService, WebhookEventsListener,
            WebhooksBootstrapService, LoggerService
  delivery: at-least-once, exponential backoff, DLQ
  security: HMAC-SHA256 signature, timingSafeEqual verification

analytics/
  responsibilities: impression tracking, click events, widget analytics

api-keys/
  storage: never plaintext; HMAC-SHA256(secret, pepper), stored hash only
  format: prefix + publicId + secret

feature-flags/
  scope: per-tenant toggles, no redeploy required

health/
  endpoints: GET /api/v1/health (liveness), GET /api/v1/health/ready (readiness with Prisma)

BR-SEC-001: all queries scoped by tenant_id, zero cross-tenant
BR-SEC-002: API Keys never stored plaintext
BR-WEB-001: webhook delivery at-least-once, HMAC signed
BR-WEB-002: outbox_events written in same DB transaction as domain event
